**Цель:** перенести сервер «Покрытие» из занятия Т4.Б1.1 с сокетов на фреймворк FastAPI, увидеть, какую работу фреймворк берет на себя, описать входные и выходные данные моделями Pydantic и получить автоматическую документацию программного интерфейса.

> **Правило работы.** Код пишется в двух файлах папки `server`: `basics.py` (задание З1) и `main.py` (задания З2–З6). Места, которые нужно дописать, отмечены комментарием `# <--`. ## Подготовка

1. Откройте папку `ПР_FastAPI` в VS Code и терминал в папке `server`:
   ```
   cd server
   ```
2. Установите библиотеки (через школьное зеркало PyPI, как в Теме 1):
   ```
   python -m pip install -r requirements.txt
   ```
   Вместе с FastAPI установятся сервер Uvicorn, библиотека httpx для тестового клиента и команда `fastapi`.
3. Проверьте, что тесты запускаются: `pytest`. Сейчас почти все тесты красные: так и должно быть. Несколько тестов зеленые сразу, они проверяют готовые части.
4. Запустите приложение:
   ```
   fastapi dev main.py
   ```
   Откройте http://127.0.0.1:8000/docs. Страница документации работает уже сейчас, хотя код почти пустой: FastAPI строит ее сам. Главная страница http://127.0.0.1:8000/ пока отвечает `{"detail":"Not Found"}`: это задание З2.

Если Windows пишет, что команда `fastapi` не найдена, запускайте так: `python -m fastapi dev main.py`.

Если страница `/docs` осталась белой, браузер не смог скачать ее скрипты из интернета (сеть доставки контента cdn.jsdelivr.net). Скажите преподавателю: он положит три файла в папку `static/docs`, и документация заработает без интернета (готовый модуль `offline_docs.py`).

Команда `fastapi dev` следит за файлами: после сохранения `main.py` сервер перезапускается сам, в терминале появляется строка о перезапуске. Перезапускать его вручную не нужно. Остановка – Ctrl+C.

## З1. Повторение: подсказки типов и декораторы (`basics.py`)

FastAPI построен на двух возможностях Python. По **подсказкам типов** он проверяет данные запроса и строит документацию. **Декоратором** `@app.get("/")` он записывает функцию в таблицу маршрутов. Повторим обе возможности на маленьких функциях.

1. **Подсказки типов.** Добавьте подсказки параметрам и результату трех готовых функций:

   | Функция | Параметры | Результат |
   | --- | --- | --- |
   | `braking_distance(v, mu, t=1.0)` | три числа `float`, у `t` значение по умолчанию остается | `float` |
   | `surface_name(code)` | строка `str` | `str \| None`: название или `None` для неизвестного кода |
   | `average_distance(distances)` | список чисел `list[float]` | `float \| None` |

   Тело `average_distance` напишите сами: для пустого списка – `None`, иначе среднее, округленное до 0,1 функцией `round(..., 1)`.
2. **Декоратор `count_calls`.** Он считает вызовы функции: после `@count_calls` у функции появляется атрибут `calls`. Схема записана в описании функции. Обязательно поставьте над оберткой `@functools.wraps(func)`, иначе обертка потеряет имя и подсказки типов. Оберните декоратором все три функции из пункта 1.
3. **Декоратор с параметром `register(path)`.** Он работает так же, как `@app.get(path)`: записывает функцию в словарь `ROUTES` под ключом `path` и возвращает ту же функцию. Допишите одну строку внутри `decorator`. Готовая функция `dispatch(path)` находит функцию в `ROUTES` и вызывает ее, как маршрутизация в Т4.Б1.1.

*Считаем на бумаге.* `average_distance([10, 20, 30.5])`: (10 + 20 + 30,5) / 3 = 20,17, после округления 20.2.

## З2. Маршруты из Т4.Б1.1 на FastAPI

Перенесите страницы сервера из Т4.Б1.1. Сравните, сколько кода понадобится теперь.

| Адрес | Метод | Ответ | Как сделать |
| --- | --- | --- | --- |
| `/` | GET | главная страница `pages/index.html` | `@app.get("/", response_class=HTMLResponse, include_in_schema=False)`, вернуть `read_page("index.html")` |
| `/surfaces` | GET | страница `pages/surfaces.html` | так же |
| `/index.html`, `/home` | GET | 301, заголовок `Location: /` | два декоратора над одной функцией, вернуть `RedirectResponse("/", status_code=301)` |
| `/static/style.css`, `/static/logo.svg` | GET | файлы из папки `static` | одна строка `app.mount("/static", StaticFiles(directory=STATIC_DIR), name="static")` |
| `/api/surfaces` | GET | список покрытий в формате JSON | вернуть список словарей `{"code", "name", "mu"}` по словарям `SURFACE_NAMES` и `SURFACE_MU` |
| `/nowhere` | любой | 404 | ничего писать не нужно |
| `POST /surfaces` | POST | 405 и заголовок `Allow: GET` | ничего писать не нужно |

`response_class=HTMLResponse` говорит FastAPI, что функция возвращает текст HTML: ответ уйдет с заголовком `Content-Type: text/html; charset=utf-8`. Без него строка ушла бы как JSON в кавычках. `include_in_schema=False` убирает страницу из документации: документация описывает программный интерфейс для программ, а страницы предназначены людям.

## З3. Калькулятор тормозного пути `GET /api/braking`

В Т4.Б1.1 функция `read_number` разбирала и проверяла каждый параметр вручную. Теперь то же самое делают подсказки типов. Параметры функции, которых нет в пути адреса, FastAPI берет из параметров запроса после знака `?`.

```python
def braking(
    v: Annotated[float, Query(gt=0, le=200, description="Скорость, км/ч")],
    ...
```

`Annotated[float, Query(...)]` означает: тип `float` и дополнительные сведения для FastAPI. `gt=0` – больше 0 (greater than), `le=200` – меньше или равно 200 (less or equal). Есть еще `ge` (больше или равно) и `lt` (меньше).

| Параметр | Тип | Ограничения | По умолчанию |
| --- | --- | --- | --- |
| `v` – скорость, км/ч | `float` | больше 0, не больше 200 | нет, обязательный |
| `mu` – коэффициент сцепления | `float` | больше 0, не больше 1.2 | нет, обязательный |
| `t` – время реакции, с | `float` | больше 0, не больше 3 | 1.0 |

Ответ – словарь `{"v": 60.0, "mu": 0.7, "t": 1.0, "braking_distance": 36.9}`. Тормозной путь считает функция `braking_distance` из З1.

*Считаем на бумаге.* $v = 60$, $\mu = 0{,}7$, $t = 1$: $60 / 3{,}6 = 16{,}7$ м за время реакции и $3600 / 177{,}8 = 20{,}2$ м торможения, всего 36,9 м.

Проверка: `pytest tests/test_z3.py`, затем http://127.0.0.1:8000/api/braking?v=60&mu=0.7 и http://127.0.0.1:8000/api/braking?v=-10&mu=0.7 в браузере. Chrome и Edge показывают над ответом JSON флажок форматирования: включите его, чтобы ответ читался легче.

Это лучше или хуже для программы-клиента? в) Откуда FastAPI знает, что скорость должна быть положительным числом? г) Почему при ошибке в параметрах функция `braking` даже не вызывается? ## З4. Модели Pydantic и `POST /api/trips`

Поездка приходит в теле запроса в формате JSON:

```json
{"date": "2026-11-05", "distance": 12.5, "surface": "wet", "note": "дождь после обеда"}
```

Вместо функции `validate_trip` из Т4.Б1.1 опишите поездку **моделью Pydantic**: классом-наследником `BaseModel`, у которого каждое поле имеет тип и ограничения.

1. Допишите перечисление `Surface(StrEnum)`: четыре значения `dry`, `wet`, `dirt`, `snow`. Перечисление (`Enum`) – тип с заранее заданным списком значений. Любое другое значение FastAPI отклонит сам.
2. Опишите модель `TripIn`:

   | Поле | Тип | Ограничения |
   | --- | --- | --- |
   | `date` | `datetime.date` | дата в виде ГГГГ-ММ-ДД, которая есть в календаре (проверяется типом) |
   | `distance` | `float` | `Field(gt=0, le=2000)`: больше 0 и не больше 2000 км |
   | `surface` | `Surface` | одно из четырех значений перечисления |
   | `note` | `str` | `Field(default="", max_length=200)`: необязательное, не длиннее 200 символов |

3. Допишите `create_trip(trip: TripIn, request: Request)`:
   - в декораторе укажите код ответа `status_code=201` (201 Created – «запись создана»);
   - превратите модель в словарь: `record = trip.model_dump()`;
   - добавьте номер `record["id"] = len(TRIPS) + 1`, время приема `record["created_at"] = datetime.datetime.now().replace(microsecond=0)` и служебное поле `record["client_host"] = request.client.host` (адрес компьютера, с которого пришел запрос);
   - сохраните запись в список `TRIPS` и верните ее.

Параметр типа `TripIn` FastAPI берет из тела запроса, параметр типа `Request` – сам запрос. Если тело не проходит проверку, FastAPI отвечает 422 и перечисляет **все** ошибки сразу, а функция не вызывается.
